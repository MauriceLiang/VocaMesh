# UX 决策记录 · VocaMesh（v1.2）

> 记录“已定 / 原因 / 备选 / 未决”，供负责人评审。来自实施文档 §2 的 21 条决策 + 本轮设计中的落地判断。

## A. 不可变更的产品决策（本设计严格遵守）

| ID | 决策 | 设计落地 |
|---|---|---|
| D01 | 任务优先 | 默认页 = 工作台；输入区是首屏第一焦点；组织架构不占首屏 |

| D03 | 单层分组导航 | 11 个入口，三组（工作 / Agent 与协作 / 应用），无第二常驻侧栏 |

## B. 本轮设计判断（含备选）

### B1 侧栏宽度 240 / 200 / 60
- **已定**：≥1080px 用 240（可读性优先），1080–980 用 200，用户可折叠为 60（图标 + Tooltip）。
- **原因**：中文标签在 232 以下容易截断；README 建议 232–248。
- **备选**：全宽度固定 248（更宽松，但 1024 下正文变窄）。

### B2 任务详情不做 50:50 分栏
- **已定**：单列连续布局（流程 → 对话 → 输入），检查器插入右侧。
- **备选**：左右分栏（流程固定左、对话固定右）。放弃原因：1280 下两侧都过窄，且不符合“连续主内容”。

### B3 审批卡在对话流中的位置
- **已定**：原型将“待你决定的审批卡”置顶于对话区（有未决项时），随后是历史消息。
- **原因**：审批是当前唯一阻塞项，不应被滚动历史淹没。
- **备选**：严格时间序（更“真实”，但需滚动才能看到决定入口）。

### B4 计数徽标使用中性色
- **已定**：待审批/未读计数使用中性白底 + 细边。
- **原因**：避免色彩泛滥；真正的风险由页面内状态色承担。
- **备选**：待审批用琥珀。评审时可切换（仅两处样式）。

### B5 部分完成的语义色
- **已定**：`部分完成` 使用**琥珀（阻塞类）**，而非绿色。
- **原因**：结果不完整，不能让用户误认为成功；同时提供“已完成/跳过/失败”分组明细。
- **备选**：中性灰（更保守）。

### B6 单 Agent 任务的顶部动作
- **已定**：显示 `暂停 / 停止`，不显示“停止派发”等主管专属动作；输入区标注“发送给：<目标 Agent>”。
- **原因**：D07 的视觉落地。

### B7 定向指令的投递状态
- **已定**：四段式 `排队 → 已送达 → 等待安全投递点 → 已应用`，并显示“已同步主管（结构化事件）”。
- **未决**：真实适配器是否支持增量输入；不支持时以“等待安全投递点 + 替代方案”呈现。

### B8 企业能力入口
- **已定**：仅在 S09（团队级权限覆盖占位）与 S13（权限与安全说明）预留，不新增多租户菜单。
- **未决**：管理员策略、审批角色、审计导出属于后续版本。

### B9 关闭窗口 vs 退出应用
- **已定**：S13 提供两种行为选择，并明确“后台运行取决于核心进程部署方式（原型不承诺）”。
- **未决**：正式架构确定后补齐真实文案与菜单项。

### B10 灰度与减少动效
- **已定**：设置中提供“灰度预览”（T24 走查）与“减少动态效果”；同时遵循系统 `prefers-reduced-motion`。
- **原因**：状态不只依赖颜色是本设计的硬约束。

## C. 已知取舍 / 与实施文档的差异

1. **画布与原型双份呈现**：高保真画布（`VocaMesh.pen`）用于设计评审与像素走查；原型用于交互验证。两者共享同一套令牌与状态文案，但**不是**自动同步的单一源（正式工程建议以原型 CSS 变量 + 画布组件为准并合并）。
2. **关系图**：原型中是树形节点的静态可视化；未实现拖拽连线（D08 已说明不需要拖拽作为唯一方式）。
3. **日志量**：原型固定 14 行 + “共 231 行”的元信息；未实现真正的增量流式与虚拟滚动。
4. **审批“任务内授权”**：按 D18 与实施文档要求，仅在具备撤销能力时提供；原型显示禁用态 + “规划中”。
5. **通知**：不重复提供审批操作，只做跳转（避免第二套审批中心）。
6. **截图证据**：本机浏览器面板宽度受限（400px 视口 + 截图拼接伪影），因此验收以**画布高保真截图 + DOM 几何断言**为证据；原型视觉请在本机 1280×800 窗口打开核对。

## D. 提交评审的问题

1. 侧栏 240 是否改为 248（更宽松）？
2. “部分完成”用琥珀还是中性灰？
3. 待审批计数是否使用琥珀（与状态色一致）？
4. 任务详情中审批卡置顶 vs 严格时间序，哪个更符合预期？
5. 是否需要在首版加入“任务内授权 + 撤销”能力（会显著增加核心复杂度）？
