## 核心设计选择及理由

**黑白灰主题与三类状态色的使用边界**
选中=中性背景 + 轻阴影 + 字重；焦点=2px 独立高对比轮廓。绿色只出现在“已完成/成功/可用/已允许”，红色只用于“失败/异常退出/不兼容/已拒绝”，琥珀只用于“等待审批/已阻塞/需登录/部分完成/冲突风险”。运行中、排队、已暂停、状态未知一律中性灰，避免色彩语义泛化。

**桌面按钮/控件圆角、阴影与密度规范**
圆角 4（badge）/6（控件）/8（卡片）/10（对话框），不使用胶囊按钮；阴影仅两档（选中、浮层/对话框），每档都为暗色单独取值；紧凑密度只改行高 34→30、控件 32→28、内边距 26→20、正文 13→12.5，不改语义。

**左侧导航分组、选中与新手路径**
240px 展开、完整中文标签；三组标题用 10.5px 弱化文本；选中不依赖颜色；待审批与未读使用中性计数徽标；底部固定设置/帮助；折叠为 60px 图标条 + Tooltip。新手路径在 S16 与空状态中以“去本地工具 / 去 Agent 角色”文本链接给出。

**任务优先的工作台布局**
首屏第一焦点是任务输入区（含工作空间、执行方式三选一、授权边界提示），第二焦点是进行中任务与待审批，第三是最近完成。组织架构、命令流与资源监控都不进首屏。

**主管对话与任务进度如何融合**
单列连续布局：顶部状态与动作 → 摘要计数 → 执行流程（子任务、依赖、状态）→ 主管对话（消息 + 审批卡）→ 底部输入。提供“流程聚焦/对话聚焦”轻量切换，但两者始终同屏可见。原始日志只在检查器中。

**右侧 Inspector 何时展开**
默认关闭；点击子任务或“检查器”按钮展开，自动定位该子任务；≤1080px 变为覆盖抽屉，避免挤压正文。

**权限审批如何避免中断正常操作**
内联审批卡（不弹全屏模态），同时顶部横幅 + 侧栏计数 + 通知跳转；任务内与“待审批”页共享同一条记录；拒绝后不重试、不绕过；超时进入“已过期”而非自动批准；更宽授权仅在具备撤销能力时提供（当前标为“规划中”）。

**暂停、继续和重试的真实语义如何传达**
暂停分两段：`等待暂停（已停止派发，当前执行仍在运行）` → `已暂停（到达安全边界）`；停止分两段：`正在请求停止` → `已停止 / 停止失败 / 状态待确认`；重试明确“创建新 Run，旧 Run 与产物保留”，并在历史页给出新旧关系。

## 设计与运行时的边界

- **演示模拟了哪些动作**：工具扫描与认证验证、任务创建与排队→执行、暂停/停止/继续、重试（新 Run）、跳过生成部分成果、审批允许/拒绝、定向指令四段投递、主管回复、日志检索、通知已读、团队环检测、并发调整提示。
- **依赖未来 Rust Core / CLI Adapter 的能力**：安全边界信号、进程停止确认、增量输入投递、真实日志流、工具探测与认证状态、Run 不可变历史、并发与队列、目录冲突检测与隔离、关闭窗口后的后台执行。
- **尚不能确认的真实能力**：执行中增量指令是否被某 CLI 支持；任务内授权的可撤销范围；跨设备/团队共享；关闭应用后的进程生命周期。

## 提交给项目负责人的审阅事项

1. 侧栏宽度最终取 240 还是 248？240 在 1024 下正文更宽，248 更宽松但更早触发折叠。
2. “部分完成”用琥珀（当前）还是中性灰？前者更醒目但可能与“等待审批”混淆。
3. 待审批计数徽标保持中性，还是改为琥珀以强化风险？
4. 任务详情中“待你决定的审批卡”置顶于对话区（当前），还是严格按时间序排列？
5. 是否在首版实现“任务内授权 + 撤销”（显著增加状态机与审计复杂度）？
6. 关系图正式渲染方案（本轮为静态占位可视化）。

## 本轮修正（相对上一版原型）

| 问题 | 处理 |
|---|---|
| 执行中/处理中动画是**实心弧线整体自转**，视觉上像圆圈本身在转 | 改为**虚线圆环整体旋转**（`stroke-dasharray: 5 7.4`、`stroke-width: 2.4`、`1.1s linear infinite`），11px badge 内仍可辨认为虚线；减少动效时静止 |
| 部分控件为“演示占位”（无行为） | 全部补齐：模板库、筛选菜单、行内菜单、工具配置/路径/指南/错误、角色工具切换与删除、团队增删成员、工作空间新建与边界、历史导出与加载更多、通知移除、帮助搜索与反馈、剪贴板与 CSV 下载 |
| 行菜单点击无反应（上下文未建立） | `openMenu` 先生成 `{kind,id}` 上下文再取菜单项 |
| 弹窗/面板内部点击会误关 | 只在点击遮罩背景时关闭 |

全量点击冒烟：14 个页面 + 15 个弹窗，共 **200 次点击、0 异常、0 空处理器**（DOM 中所有 `data-action` 均命中实现）。

## 待解决项与限制

1. **截图取证**：本机集成浏览器面板仅 400px 宽且截图存在拼接伪影，因此视觉证据采用画布导出图；原型请在本机 1280×800 窗口复核。
2. **键盘走查**：已保证 `focus-visible` 样式、`aria-current`、`aria-label`、`Esc`、`⌘K`、`Enter` 发送；未逐项验证焦点陷阱与顺序，需人工复核。
3. **900×650**：设置/帮助需滚动侧栏才能到达（符合“可滚动可达”，非首屏可见）。
4. **占位能力（已大幅收窄）**：关系图不支持拖拽连线；无持久化（刷新复位）；无真实 OS 通知；审批“任务内授权”仍为带说明的禁用项。
5. **暗色对比度**：边框在暗色下较难辨识，已通过“选中背景差 + 字重 + 阴影”三重线索补偿，仍建议高对比模式单独走查。
6. **本轮未做**：真实窗口边框截图、录屏、多语言、企业多租户管理界面。
