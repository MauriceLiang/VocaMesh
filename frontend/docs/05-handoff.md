# 前端交接说明（给 Rust / 后续开发）

## 1. 已完成

- 14 个显式页面路由 + 1 条兜底重定向与桌面外壳（标题栏、固定侧栏、顶栏、命令面板、Toast）。
- 14 个通用组件（Voca*），其中弹窗/下拉/选择/开关/复选框/标签页/提示用 Reka UI 封装。
- 10 个 Service 接口 + Mock 实现（内存唯一数据源），Pinia Store 分离业务状态。
- 任务 Store 统一订阅任务状态事件并合并任务；加载列表与状态事件竞态时保留较新的事件状态。
- 状态筛选写入内部状态码；创建时间筛选按 ISO 8601 `createdAt` 过滤，未知时间只出现在“全部时间”。
- 团队/单 Agent 创建按选定 ID 解析执行者；自定义执行只创建待配置占位，不生成子任务/依赖或模拟启动。
- 工作台“已完成”使用任务 Store 总计数；失败、需处理、部分完成使用各自统一语义色。
- 关系图使用 Vue Flow（自定义节点 + 平移/缩放/拖拽 + 节点菜单 + 环检测）。
- 主题/密度/灰度/平台切换，窗口缩放适配（≤1080 检查器抽屉）。
- 单元测试（Service 契约、状态语义）与 Playwright（导航、任务链路、关系图、视觉截图）脚本。

## 2. 仍由 Mock 提供的能力

| 能力 | Mock 行为 | 需要 Rust 提供 |
|---|---|---|
| 工具探测/认证 | 固定 4 条 + 状态迁移 | PATH/版本/登录状态读取；**不得读凭据** |
| 任务执行 | 团队/单 Agent 任务由定时器模拟状态迁移；自定义占位保持 `draft` | 真实调度的状态事件（含安全边界） |
| 暂停/停止 | 定时器 → 目标态 | 运行时确认信号（失败/超时也要有） |
| 重试 | 生成新 runId | Run 不可变存储与关联 |
| 日志 | 14 行回放 + 心跳 | 流式日志 + 背压/截断 |
| 审批 | 内存记录 | 授权作用域校验、撤销、审计 |
| 定向指令 | 四段定时 | 适配器能力探测、投递确认 |
| 工作空间 | 内存对象 | 真实目录校验与边界执行 |
| 设置 | 内存 | 持久化；窗口/退出行为需桌面进程配合 |

## 3. 对接点（只改一处）

1. 新建 `src/services/tauri/*.ts` 实现 `services/contracts/*` 的接口。
2. 在 `src/services/adapters/index.ts` 增加 `createTauriServices()` 并切换 `useServices()`。
3. 事件用 `listen()` 包装为 `subscribe*(): () => void`；任务状态由 Store 单一订阅并随 Store 生命周期清理，组件级日志订阅仍需离开检查器时取消。

> 不要在前端伪造 Rust 命令名。命令/事件名以 Rust 侧实现为准，前端只按接口签名对接。

## 4. 已知问题 / 风险

1. **验证状态**：本轮构建、单元测试、E2E 与视觉对照记录见 `docs/06-test-report.md` 和 `docs/04-visual-diff.md`。完整 Playwright 用例使用系统 Chrome 通过；标准 Chromium 下载受网络/文件系统限制，复跑方式见测试报告。
2. **Mock 边界**：任务状态定时器、内存数据、日志心跳、审批与指令状态都是演示行为，不证明真实 Agent 执行或 Rust/Tauri 运行时。
3. **自定义执行**：计划编辑契约尚未实现；当前只创建 `draft` 待配置占位任务，不创建依赖图，也不自动迁移到 `running`。
4. **团队与 Agent**：创建表单只提供主管与 Agent 状态为可用的选项；真实运行时仍需再次校验执行环境与权限。
5. **时间筛选**：只使用 `createdAt`；缺失/非法/未来时间戳在 7/30 天范围内不显示，“全部时间”仍可见。该字段不是最后更新时间。
6. **Vue Flow 样式**：`@vue-flow/core` 默认主题与原型不同，已在节点内覆盖；`Controls`/`MiniMap` 未启用，后续启用需重新对齐视觉。
7. **Toast / 弹层 z-index**：`.v-toasts` 90、`.v-menu` 75、`.v-dialog` 70；新增浮层时请沿用该层级。
8. **导出与权限**：CSV/Markdown 为前端 Blob 下载；前端权限开关只呈现配置，真实权限执行必须由 Rust 侧强制。
